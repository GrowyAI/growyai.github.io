# 小游戏视觉约定（Visual Convention）

> 适用范围：`/zh/games/` 下的游戏大厅与 4 个小游戏。
> 本文是**约定文档，不是代码依赖**：页面不引用它，它也不被任何页面加载。
> 建立于 2026-11-08，第 1 版。

---

## 1. 目标与边界

**最高原则：没有必要的元素一律不加。** 编号、箭头、装饰性圆点、多余图标或分割线——凡不承担信息或交互功能的，都不加。层级用留白、细边和柔和阴影表达，而不是靠新增图形。宁可少一个元素，不要多一个。

**风格目标**：轻松、愉快、安静；低饱和的淡雅彩色。
**降饱和力度**：只降一点，不做整体灰度化。明快感来自大留白、柔和阴影和轻微动效，不来自高饱和底色。
**主题色不统一**：每个游戏内容不同，各自保留一个可识别的主色；统一的是**用色方式、形状语言、排版层级与交互反馈**。

**必须保留的产品特征**

- emoji 是内容主体，也是这个产品的重点：**游戏内与大厅卡片图标统一轻微降饱和**（`--emoji-sat`），但不替换字符、不改 `words/data.js` 里的任何一个 emoji 数据。
- 4 个游戏各自独立：单文件 `index.html` + 内联 CSS/JS，`file://` 双击可用，可单独搬运或删除。
- 玩法逻辑、关卡数据、判题规则一律不动。

**本轮明确不做**

- ❌ 返回大厅入口。4 个游戏都需要，但留到统一 UI 之后单独一轮处理（位置、极简图标样式需另行讨论）。
- ❌ 统一对错反馈的语义色。各游戏保留自己的对错表达，只要求**同一游戏内部**一致。
- ❌ 大改「数学挑战」。单独看它是明快好看的小游戏，只做外壳微调。
- ❌ 抽 `theme.css` / 公共 JS。会破坏独立性。

## 2. 现状判断与问题定位

| 页面 | 判断 | 需要处理 |
| --- | --- | --- |
| `index.html` 大厅 | 暖白渐变 + 白卡 + 20px 圆角 + 柔和阴影 + 暖棕文字 | **基准**；卡片 UI 不动，仅卡片图标里的 emoji 随全局降饱和 |
| `words/` 词汇卡 | 最贴近大厅；设置面板已是基准语言 | 等待态半透明的饱和度 |

### 2.1 数字点点：为什么"一大串纯绿"不好看

`drawMenu()` 把 5 个模式画成 5 个**完全一样**的实心 `#6fae6a` 圆角矩形 + 白色粗体字，铺在 `#eaf7ff` 上：

- 同一屏出现 5 次大面积同色实心块，视觉重量重复且单调；
- 实心绿 + 白字的对比度偏低，靠 `bold 19px sans-serif` 撑可读性，显得"用力"；
- 和游戏内白蓝渐变的盘子、和大厅的白卡片列表都不是一套语言；
- 选关下拉 `drawLevelMenu()` 又用另一套绿（`#6fae6a` 文字 + `rgba(111,174,106,.14)` 高亮），两处绿色互不相干。

**方向（用户复核后定稿）**：回到实心按钮，但 5 个模式用 **5 种低饱和淡彩**，深浅只比 `#eaf7ff` 画布底色**深一点**；文字保持深蓝 `#2b5876`、居中；20px 圆角。**不加描边、阴影、编号、箭头、图标或任何装饰**——区分 5 个模式靠颜色与文字本身，不靠新增元素。`PALETTE.menuButtons` 存这 5 个色值，`menuButtons` 的几何与命中逻辑不变。

> 复盘（两次被否，避免再走回去）：
> 1. 中间版本曾加 5 个淡彩序号圆点和右侧 `›`，属于"为了区分而新增元素"，违反 §1 最高原则，已移除；
> 2. 之后改成"白卡列表"（白底 + 1px 细边 + 柔和阴影），用户复核后仍不满意（原话：「还是丑。还不如之前的」），明确要求改回实心按钮、用几种低饱和彩色。白卡版已移除。

### 2.2 写写画画：上下两条选择栏"别扭"的具体成因

两条栏做的是**同一件事**（从一组可选项里选一个），却用了两套不同的语言：

1. **字号字重脱节**：顶栏 `21px / 800`，底栏 `20px / 700`；而大厅卡片标题是 `18px / 600`、正文 `14.5px / 400`。两条栏比全站任何文字都更大更重，像是另一个产品。
2. **混排字形密度不一致**：顶栏同时有 `123` `ABC` `abc` `▲◆` 和中文「数字 / 生肖 / 衣食 / 住行」，同一字号下拉丁大写与汉字的视觉大小差很多，行内忽大忽小。
3. **两套形状语言**：顶栏是"白色药丸里的胶囊标签"，底栏是"整宽白色渐变幕布上的 48px 圆形按钮"；一个是浮起的小组件，一个是贴边的大底板，层级关系不同。
4. **两套选中态 / 按压态**：顶栏选中 = 分类实心色 + 白字；底栏选中 = 固定橙色 `#FF8C42` + 白字 + `scale(1.1)`，而 `:active` 又是 `scale(0.9)` —— 选中态自己会放大、按下又缩小，两种 transform 互相打架，相邻项还会视觉抖动。底栏用固定橙色，和顶栏"按分类变色"也没关系。
5. **两套滚动规则**：顶栏 `overflow-x:auto` + 点击后 `scrollIntoView(center)`；底栏多一套 `scroll-snap`，两条都隐藏滚动条、都没有"还能往右滑"的提示，最后一项被切掉时不知道可以滑。
6. **点击区不一致**：顶栏实际高约 35px，底栏 48px，都低于/接近 44px 的舒适触控下限。

**方向**：把"选择器"当成一个组件，两条栏共用同一套字号、字重、最小点击高度、选中态、按压态、滚动规则与容器外观；底栏选中色改成**跟随当前分类色**，不再固定橙色；分类色只做轻微降饱和，保留可区分度。

### 2.3 词汇卡：等待态与成功态的对比不够强

`.display-emoji.dim` 只有 `opacity: .3`。半透明之后 emoji 的**饱和度仍在**，看起来像"变淡的彩色图"，而不是"还没解锁"。完成后移除 `dim` 并播放 `pop`，两者的差别主要是亮度，不够有仪式感。

**方向**：等待态同时降低透明度与饱和度（`opacity` + `filter: saturate()`），成功时回到常态并 pop。emoji 字符与数据一律不改；常态 emoji 另由 `--emoji-sat` 统一轻微降饱和。

## 3. 共用 token（每个文件各自内联一份）

命名固定，**值可以不同**。每个 `<style>` 顶部自带一份 `:root`；canvas 游戏在 JS 里放一个同名 `PALETTE` 常量，供绘图代码引用。不新增任何被多个页面加载的文件。

```css
:root {
  --bg:            /* 大面积底色，近白，可两段淡渐变 */
  --bg-2:          /* 次一级底色 / 卡片浅底 */
  --surface:       #ffffff;
  --text:          /* 主文字，深暖棕或深蓝灰 */
  --muted:         /* 次要文字 */
  --faint:         /* 提示文字 */
  --accent:        /* 本页唯一主色，低饱和 */
  --accent-soft:   /* accent 的 10~14% 浅色底 */
  --accent-ink:    /* accent 同色系深字，用于选中态 */
  --line:          rgba(120,108,90,.10);
  --shadow:        0 6px 20px rgba(120,108,90,.07);
  --r-sm:          12px;
  --r-md:          20px;
  --r-lg:          28px;
  --emoji-sat:     0.85;  /* emoji 统一饱和度，1 = 原色；大厅 + 四个游戏共五页保持同一数值 */
}
```

各页建议值（保留各自识别度，只降一点饱和）：

| 页面 | `--bg` | `--text` | `--accent` | `--accent-soft` | `--accent-ink` |
| --- | --- | --- | --- | --- | --- |
| 大厅 | `#fdfbf7 → #f5f6f2` | `#2b2622` | 暖杏 `#e0a87f` | `#faf0e7` | `#a2694a` |
| 词汇卡 | `#f7f4f0` | `#1a1a1a` | 鼠尾草 `#b8d4a8` | `#f1f8ea` | `#4a7d5c` |
| 数字点点 | `#eaf7ff` | `#2b5876` | 雾蓝 `#8fb2c9` | `#eaf2f7` | `#3f6b85` |
| 写写画画 | `#e0f7fa` | `#4a4640` | 淡青 `#8fc4c8` | `#eaf4f4` | `#3f7478`；分类色另成一组同饱和度淡彩 |
| 数学挑战 | 保留水下蓝渐变 | `#4a4640` | 杏橙 `#dfa87c` | `#faf0e7` | `#a2694a` |

> 数学挑战是**例外页**：背景渐变、波光、气泡、5 套鱼配色、橙猫、成功 toast、对错飘字都保留，只在弹窗/顶栏这些"外壳"上向约定靠拢。

## 4. 组件规则

### 4.1 选择器（顶栏分类 / 底栏条目 / 选关列表通用）

- 字号 `16–17px`，字重 `600`；不再用 `21px/800`、`20px/700`。
- 最小点击高度 `44px`，左右内边距 `≥14px`。
- 选中态 = `--accent-soft` 底 + `--accent-ink` 字 + 1px 同色系细边；默认态 = 透明底 + `--muted` 字。
  - 例外：写写画画的分类色承担"内容分类"作用，允许用轻微降饱和后的实心分类色 + 白字，但**上下两条栏必须用同一个色值**。
- 按压态统一 `transform: scale(.97)`，`0.15s ease`；**不要用选中放大**（`scale(1.1)`）和按压缩小混用。
- 滚动统一：`overflow-x:auto` + 隐藏滚动条 + `scroll-snap-type: x proximity` + `scroll-padding-inline`；点击后 `scrollIntoView({ inline:'center' })`。最后一项轻微切边本身就是"还能往右滑"的提示，不要再叠一层渐变遮罩（会把胶囊的圆角一起吃掉）。
- 容器外观统一：浮起的白色胶囊/条，`--r-lg` 圆角、1px 细边、`--shadow`；不要一条是浮起药丸、另一条是贴边白幕。

### 4.2 卡片与弹窗

- 1px `--line` 细边 + `--shadow` + `--r-md` / `--r-lg` 圆角。
- 不用 3–4px 彩色粗边，不用 `0 5px 0` 之类的硬偏移"立体"投影。
- 遮罩用暖深色半透明（如 `rgba(48,40,34,.42)`），不用纯黑。

### 4.3 按钮

- 一屏只放 1 个主按钮（用 `--accent`）；次按钮用 `--bg-2` / 米色 + `--muted` 字。
- 主按钮文字与底色对比度 ≥ 4.5:1（大号粗体 ≥ 3:1）。
- 保留橙/绿等识别色，但渐变只在同一色相内做 2 段轻微明度变化。

### 4.4 字体与排版

- 统一字体栈：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif`，emoji 后附 `Apple Color Emoji / Segoe UI Emoji / Noto Color Emoji`。
- 标题 `600–700`，正文 `400–500`；三档字号即可。
- canvas 文本用同一字体栈与字重，不用裸 `bold … sans-serif`。
  - 本轮只迁移 UI 层文本（标题、菜单、按钮、返回、选关、继续）；盘子/容器上的内容数字沿用旧字体，后续按页面逐步替换。
- 圆角只用三档：`--r-sm` 徽章 / `--r-md` 卡片按钮 / `--r-lg` 弹窗与选择器容器。

### 4.5 状态与动效

- 对错反馈**不跨游戏统一**；同一游戏内保持一致即可。
- 半透明等待态：降透明度 + `filter: saturate(.3~.4)`；成功态回到常态并用已有的 `pop` 动效，形成"灰淡 → 鲜亮"的对比。
- 过渡 `0.15–0.25s ease`；保留已有的轻微呼吸、浮动、气泡；不做大面积闪烁色块。
- 尊重 `prefers-reduced-motion`（后续新增动效时）。

### 4.6 emoji 饱和度

emoji 是内容主体，扎眼的是**整组原生 emoji 的高饱和**，不是某一个颜色值。因此不逐个改字符、不改数据文件，只在**渲染层**统一加一层很轻的滤镜：

- 每个页面自带 `--emoji-sat`（默认 `0.85`，即降 15%）；**大厅 + 四个游戏共五页保持同一数值**，调幅度只改这 5 个数字。
- **DOM emoji**（词汇卡、按钮、面板、大厅卡片图标）：`filter: saturate(var(--emoji-sat))` 挂在承载 emoji 的叶子元素上。不要挂在 `body` 或根容器 —— `filter` 会创建 containing block，破坏页面里的 `position: fixed` 弹窗。
- **canvas emoji**（数字点点的水果、写写画画的追逐图标）：给 `<canvas>` 元素加同一条 filter。因为底色、盘子、笔迹本来就是低饱和淡彩，15% 的降幅对它们几乎无感；若将来只想降 emoji、完全不动笔迹，可改用局部 `ctx.filter`（在 `ctx.save()` 内设置，画完由 `restore()` 自动复原）。
- **数学挑战例外**：鱼和猫是 canvas 手绘图形、不是 emoji，保持原样；只有标题 🐱、模式按钮 ➕➖✖️➗、成功提示 🎉 这些 UI 图标参与降饱和。
- 词汇卡等待态 `.dim` 用 `saturate(.32)`，选择器更具体，会覆盖常态滤镜，对比不被削弱。用户上传的真实照片用 `:has(img)` 排除。
- 大厅卡片图标也纳入（用户复核后补做）：filter 只挂在 5 类 emoji 叶子元素上 —— `.icon-grid span`（🍎🚗🐶🛝）、`.icon-number .berry-row`（🍓）、`.icon-cat .cat-face / .heart`（🐱❤️）、`.icon-trace .badge-pencil`（✏️）。卡片淡彩底色、渐变 `Aa`、粉色数字 `3`、右侧 `→` 都是 CSS 绘制，不参与；不为这件事新增任何 DOM 元素。返回按钮里的 🏠 是否纳入待确认。

## 6. 独立性保障

- 不新增被多页加载的 CSS/JS；`words/data.js`、`trace/hanzi-data.js` 保持原样。
- 每个文件可单独用 `file://` 打开、单独回滚、单独删除。
- token 只是"同名约定"，不是共享运行时；改一个游戏不会影响其他三个。

## 7. 验收标准

- 375 / 430 / 768px 宽度下无横向滚动，无内容被固定栏遮挡。
